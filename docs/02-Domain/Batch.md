# Batch Domain

> **Purpose**
>
> A **Batch** is the primary production planning and execution unit within a Project. It groups a collection of Assets that follow a common production workflow, share a production team, and are delivered as a logical milestone.
>
> The Batch acts as the operational boundary for production planning, resource allocation, workflow execution, progress tracking, and reporting.

---

# Overview

Projects are divided into one or more Batches.

A Batch represents a manageable production package that can be independently planned, executed, monitored, reviewed, and delivered.

The Batch is responsible for:

- Production Planning
- Team Assignment
- Resource Allocation
- Workflow Selection
- Asset Management
- Progress Monitoring
- Production Reporting
- Batch Communication

# Resource Allocation

Artists are **not directly assigned** to a Batch.

Instead, the Batch Manager raises **Resource Allocation Requests**.

```text
Batch Manager

↓

Allocation Request

↓

Resource Manager

↓

Approved

↓

Artist Allocated
```

Allocation supports:

- Allocation Percentage
- Allocation Duration
- Multiple Batch Allocation
- Capacity Planning

---

# Workflow

Every Batch is associated with a Workflow.

The Workflow defines:

- Production Processes
- Review Processes
- Available States
- Allowed Transitions

Example:

```text
Production

↓

WIP Review

↓

Lead Review

↓

Final Review

↓

QC

↓

Client Review

↓

Completed
```

Different Batches within the same Project may use different Workflows if required.

---

# Batch Stages

A Batch is divided into one or more Production Stages.

Examples:

- Modeling
- Sculpting
- Texturing
- Rigging
- Animation
- Lighting
- Rendering

Each Stage references a Workflow.

Tasks created within a Stage automatically inherit that Workflow.

The Task owner may later override the Workflow if business rules allow.

---

# Assets

A Batch contains one or more Assets.

Examples:

```text
Batch

├── Character A
├── Character B
├── Environment A
├── Vehicle A
└── Weapon A
```

Assets are the primary production items executed by Artists.

---

# Tasks

Every Asset contains one or more Tasks.

Tasks are created from the configured Batch Stages.

Example:

```text
Asset

├── Modeling
├── UV
├── Texturing
├── Rigging
└── QA
```

Each Task follows the Workflow inherited from the Batch Stage.

---

# Deliverables

Deliverables are produced by completed Tasks.

Batch-level reporting aggregates all Deliverables generated by its Assets.

The platform stores:

- Repository
- Version
- File Path
- Changeset
- Delivery Date

Actual production files remain in the external source control repository.

# Business Rules

## BR-001

Every Batch belongs to exactly one Project.

---

## BR-002

Every Batch must have one Batch Manager.

---

## BR-003

Every Batch must reference one Workflow.

---

## BR-004

A Batch contains one or more Assets.

---

## BR-005

Assets cannot belong to multiple Batches.

---

## BR-006

Tasks inherit their initial Workflow from the Batch Stage.

---

## BR-007

Artists perform work only after Resource Allocation approval.

---

## BR-008

A Task Kanban Board is maintained at the Batch level.

---

## BR-009

Batch communication is independent of Project communication.

---

## BR-010

A Batch cannot be closed until:

- All Assets are closed.
- All Tasks are closed.
- All mandatory workflow stages are completed.
- All required Deliverables are submitted.
